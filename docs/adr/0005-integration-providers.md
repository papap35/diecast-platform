# ADR 0005：金流、物流、電子發票介面化，內建模擬實作

- 狀態：採用

## 背景

台灣電商的金流、超商物流、電子發票通常由同一家服務商（例如綠界）提供。開發、測試與作品集展示時不能依賴真實帳號，也不能每次都打外部服務；但模擬的流程又必須跟真實串接一致，才不會在上線時才發現問題。

## 決策

三種服務各定義一個介面，各有兩個實作：模擬（預設）與綠界。以環境變數（`PAYMENT_PROVIDER`、`LOGISTICS_PROVIDER`、`INVOICE_PROVIDER`）分別切換。模擬實作走跟綠界相同的流程：付款也是導到另一個頁面再由伺服器通知、物流也有狀態代碼、發票也有開立／作廢／折讓。綠界共用的 CheckMacValue 簽章獨立成一個模組，單元測試的期望值由綠界官方 SDK 對同一組參數計算得出（含中文與特殊字元）。

## 考慮過的替代方案

- **只做綠界、測試時打測試環境**：測試慢且不穩定，回呼需要公開網址，本機開發不方便。
- **在測試裡 mock HTTP**：可以測試串接程式，但無法讓整個網站在沒有帳號的情況下完整運作。

## 影響

- 不需要任何帳號就能完整操作下單、付款、出貨、開發票、退款；端對端測試也走同一套流程。
- 新增其他服務商（例如藍新金流）只需要新的實作，訂單流程不變。
- 使用方式與綠界測試環境的設定見[金流、物流與電子發票](../payments.md)。
