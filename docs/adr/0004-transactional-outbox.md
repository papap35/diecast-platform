# ADR 0004：副作用以同一交易寫入待辦，由排程處理

- 狀態：採用

## 背景

訂單的狀態變化會觸發外部副作用：寄 Email、開立或作廢電子發票、站內通知。如果在交易裡直接呼叫外部服務，第三方變慢會拖住資料庫交易；如果交易提交後才呼叫，程式在中間當掉就會漏掉副作用。

## 決策

採用 outbox 模式：副作用在同一個資料庫交易裡寫成待辦資料（`EmailMessage`、待開立的 `Invoice`），交易提交才算數；背景排程取出待辦呼叫外部服務，成功後更新狀態，失敗則記錄錯誤、間隔拉長重試，超過上限交給後台人工處理。

## 考慮過的替代方案

- **交易內直接呼叫**：簡單，但第三方逾時會讓結帳失敗或卡住連線。
- **訊息佇列（例如 BullMQ）**：功能完整，但佇列與資料庫是兩個系統，寫入時仍有一致性問題，也多一個要維運的元件。

## 影響

- 訂單成立、付款入帳不受 Email 或發票服務故障影響。
- 外部服務的呼叫是「至少一次」：寄信以信件 id 作為冪等鍵，發票以狀態欄位與 Redis 鎖避免重複開立。
- 後台的寄信紀錄、發票狀態可以看到每一筆待辦的嘗試次數與錯誤原因，並手動重試。
